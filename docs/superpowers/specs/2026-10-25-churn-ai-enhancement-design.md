# 电信客户流失分析与用户排序：AI 增强设计

## 目标

在现有客户分群、流失建模和固定容量排序基础上，增加一个可解释、可离线运行的“AI 风险解读与触达建议”模块。它帮助运营人员理解某个高风险客户为什么进入优先名单、可以先采取什么沟通方向，同时保留现有统计模型作为唯一的风险排序依据。

交付后，项目仍可以在没有 API 密钥和网络的环境下运行；配置 OpenAI 兼容接口后，AI 模块能够把结构化证据整理成中文解读。AI 生成内容只作为辅助分析，不改变模型分数、测试指标或固定容量名单。

## 方案比较

### 方案 A：结构化上下文 + 可选 OpenAI 兼容接口 + 本地模板兜底（推荐）

训练流程生成经过白名单筛选的客户上下文，包括客户服务特征、风险分数、排序名次、所属分群的历史流失率和有限的业务规则证据。看板默认使用本地模板；检测到环境变量后，向兼容 Chat Completions 的接口发送同一份上下文，展示中文风险摘要、证据和建议动作。接口失败时自动回到模板，并在页面标明当前使用的模式。

优点是无需新增重量级 SDK，演示不依赖外部服务，简历中仍能清楚说明 LLM 调用边界。缺点是自然语言质量取决于配置的模型，接口调用需要用户自行提供服务。

### 方案 B：只接入本地模型

通过 Ollama 或其他本地推理服务生成解读。数据不离开本机，但需要额外安装模型和服务，首次运行成本较高，项目复现门槛也更高。

### 方案 C：只做规则模板

不接入大模型，只根据风险分数和字段规则生成固定话术。最稳定，但只能称为规则解释器，不能充分体现 AI 应用能力。

本项目采用方案 A。方案 B 作为后续可替换 Provider，方案 C 作为无服务时的必需兜底。

## 功能设计

### 1. 结构化客户上下文

在训练流程中生成 ai_customer_context.csv，仅保留训练集五折 AP 选出的主模型在测试集固定 10% 名单中的客户，并包含：

- 客户编号、主模型名称、策略名次、模型排序分数；
- 在网时长、合同类型、月费、互联网服务、付款方式、技术支持等白名单特征；
- 合同类型、在网时长和月费分组的训练集历史流失率；
- 由规则计算的风险证据标签，例如“月付合同”“在网时间较短”“历史分组流失率较高”。

actual_churn 只保留在离线评估表中，不写入 AI 上下文，不进入提示词，不在 AI 页面展示。AI 模块也不读取完整原始 CSV，避免把无关字段或测试标签带入生成环节。

### 2. AI 解读 Provider

新增轻量 ai_assistant.py，使用 Python 标准库发送可选的 OpenAI 兼容 HTTP 请求，不新增必须安装的 SDK。Provider 接口统一返回：

- mode：模板解读或模型生成；
- summary：风险摘要；
- evidence：结构化证据列表；
- actions：不超过 3 条可执行触达建议；
- limitations：数据边界和人工复核提示。

提示词要求模型只根据给定事实回答，禁止把相关性写成因果关系，禁止承诺客户一定流失或一定挽回，禁止输出真实流失标签和未经提供的客户信息。模型返回异常、超时、格式不完整或服务未配置时，统一转为本地模板结果。

建议配置项使用环境变量，不写入仓库：

    CHURN_AI_BASE_URL=
    CHURN_AI_MODEL=
    CHURN_AI_API_KEY=
    CHURN_AI_TIMEOUT_SECONDS=20

其中 BASE_URL 和 MODEL 可指向任意兼容接口；没有 API_KEY 时允许本地无鉴权服务，远程服务必须由用户自行配置。

### 3. Streamlit 看板

新增第四个“AI风险解读”页：

1. 从结构化上下文表选择一名优先客户；
2. 用中文表格展示客户特征、风险分数、排序名次和风险证据；
3. 点击按钮后生成解读；
4. 分栏展示风险摘要、证据、建议动作和限制说明；
5. 页面显示当前模式和错误兜底状态，不展示 JSON，不自动发送整张数据表。

页面默认不自动调用接口，避免刷新页面产生费用或重复请求。没有 ai_customer_context.csv 时给出生成报告的命令，不自动训练。

### 4. 简历与 README 展示

README 增加 AI 运行方式、环境变量说明、离线模板模式和一张 AI 页面截图。项目讲解材料增加：

- 为什么让统计模型负责排序、让大模型负责解释；
- 如何通过白名单上下文和提示词约束减少幻觉；
- API 不可用时如何保持 Demo 可复现；
- AI 建议不等于因果结论和真实挽留策略效果。

简历表述使用“基于结构化风险证据生成中文风险摘要和触达建议”，不写成“AI 自动决策”或“自动提升挽留率”。

## 实施顺序

1. 在 churn_pipeline.py 中增加白名单上下文和规则证据生成，扩展报告输出；
2. 新增 ai_assistant.py，实现模板 Provider、OpenAI 兼容 Provider、超时和异常兜底；
3. 在 dashboard.py 增加 AI 风险解读页，默认模板模式，配置后可调用接口；
4. 新增测试：上下文字段白名单、真实标签不进入提示词、模板结果稳定、接口失败回退、看板无 API 时无异常；
5. 更新 requirements.txt（原则上不增加必需依赖）、README、项目讲解材料和 .env.example；
6. 运行测试、编译检查、真实数据重新生成新报告，并用浏览器核验 AI 页面和原有三页没有回归。

## 验收标准

- 无 API 配置时，项目可正常训练、启动看板并生成模板解读；
- 配置兼容接口时，提示词只含白名单字段和模型证据，不含 actual_churn、完整原始数据或密钥；
- 接口超时、返回错误或返回空内容时，页面给出可理解的中文状态并回退模板；
- AI 页面不展示 JSON，不改变现有模型指标、排序名次和策略表；
- 现有测试全部通过，并新增 AI 相关测试；
- README 能让面试者用通用 python 命令分别运行离线 Demo 和可选 AI 模式；
- 文档明确 AI 输出是辅助解释，公开数据和历史标签不支持线上收益结论。

## 不纳入本轮

- 不训练新的生成模型，不做微调、RAG 知识库或向量数据库；
- 不让大模型修改风险分数、阈值、模型选择或客户名单；
- 不保存 API 密钥、客户对话或远程服务返回日志；
- 不把测试集真实标签传给 AI；
- 不实现自动发送短信、优惠券或运营动作。

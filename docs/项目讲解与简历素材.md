# 项目讲解与简历素材

## 五分钟演示顺序

1. **业务问题（30 秒）**：客户资料有限，先判断哪些客户群的历史流失比例不同；如果只能优先关注 10%，比较模型排序和简单规则能覆盖多少历史流失客户。
2. **数据与分群（60 秒）**：说明客户快照、标签含义、训练/测试拆分和分母口径；展示合同、在网时长、月费三个训练集分组。强调相关性不等于原因。
3. **模型验证（90 秒）**：逻辑回归作为容易解释的基线，随机森林作为非线性候选；预处理放在 Pipeline 中，五折 AP 只在训练集计算，测试集最后统一评估。
4. **同容量排序（60 秒）**：固定 10% 名额，比较两个模型、短在网规则和随机期望；解释 Precision@K、Recall@K、Lift@K，说明这不是挽留名单。
5. **限制与下一步（60 秒）**：数据没有事件时间和干预记录，所以不能声称未来预测或真实挽回；真实业务要按客户随机分组做 A/B 实验。

## 简历项目经历

**电信客户流失分析与用户排序｜Python、SQL、Pandas、scikit-learn、Streamlit**

- **项目背景**：基于 7,043 条公开电信客户快照，分析客户流失特征，在固定 10% 联系容量下比较风险模型与简单规则的客户排序效果。
- **个人工作**：完成数据校验和缺失值处理，通过 SQLite 分析合同、在网时长和月费分群；使用 Pipeline 实现折内预处理，以训练集五折分层交叉验证比较逻辑回归与随机森林；开发中文看板展示客户差异、模型证据与策略结果。
- **项目成果**：按训练集五折 AP 选定逻辑回归，固定测试集 ROC-AUC 为 0.8419、AP 为 0.6334；在相同 140 人名额下识别 104 名历史流失客户，比短在网规则多识别 17 人，Precision@140 为 74.29%，Lift@140 为 2.80。

- **AI 增强**：基于主模型优先名单的白名单客户上下文，增加中文风险摘要、证据整理和人工触达建议；远程 OpenAI 兼容接口可选，未配置时使用离线模板，测试集真实流失标签不进入提示词。

这里的成果是公开快照上的离线排序评估，不是降低流失率或真实收入增长。随机森林的对照结果也应保留：测试 AP 为 0.6399，固定名额命中 108 人；不能因测试结果更高而回头更换 CV 选出的模型。

简历中的具体数值应从本次 `outputs/career_v2_02/metrics.json` 和 `policy_metrics.csv` 读取。没有重新运行或结果文件不完整时，不填写指标数字。

## 常见追问

**为什么用 AP，不只看 Accuracy？**  流失客户比例低，只看整体正确率容易被多数类掩盖。AP 更关注把正类排在前面时的查准率变化，适合和固定名额排序一起解释。

**为什么要先拆训练集和测试集？**  分群和模型选择如果看到测试标签，会把最终评估集变成调参数据。当前先分层拆分，分群与五折 CV 只使用训练部分，测试集最后才用于公开基准。

**为什么比较短在网规则？**  它是业务人员容易理解的基线。模型只有在相同客户名额下比它多覆盖流失客户，才有额外排序证据。

**10% 名额是不是最佳预算？**  不是。它是预先固定的评估容量，用于公平比较；真实预算应由触达成本、团队容量和实验结果共同决定。

**高风险客户一定能挽回吗？**  不能。当前模型只学习历史流失倾向，没有干预记录，不能识别优惠带来的增量效果；需要客户级随机实验评估。

**随机策略为什么只有期望没有名单？**  随机抽取的某一份名单会随随机种子变化，数学期望更适合当稳定基线。它的 Precision@K 期望等于测试集整体流失率，Lift@K 为 1。

**为什么没有 Spark、XGBoost 或 SHAP？**  数据只有约 7,043 行，本地 SQL、线性基线与树模型足以支持当前分析目标。优先验证分群口径、模型稳定性和同容量排序效果；是否引入更多工具取决于具体数据规模和问题。

**AI 在项目中负责什么？**  统计模型负责产生风险排序，AI 负责把排序分数、客户特征和训练集分群证据整理成中文解读与人工建议。AI 不改分数、不选客户，也不接收测试集真实标签。

**没有本地模型怎么演示 AI？**  未配置远程接口时使用确定性模板，能够展示完整的风险证据和建议结构；配置 OpenAI 兼容远程接口后再启用自然语言生成。本项目不接入本地模型服务。

**这个项目能证明业务收益吗？**  不能。它证明了数据清洗、分群、模型验证和同容量离线排序能力；真实收益需要固定模型后做随机对照实验，并观察完整结果窗口。

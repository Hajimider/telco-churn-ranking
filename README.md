# 电信客户流失分析与用户排序

基于 Telco Customer Churn 数据，分析合同类型、在网时长和月费与历史流失的关系，并比较逻辑回归、随机森林在固定联系名额下的排序效果。

项目使用 Pandas 清洗数据、SQLite 统计客户分群、scikit-learn 训练和评估模型，通过中文 Streamlit 看板查看结果。所有评估均在离线数据上完成。

## 实验结果

一次已保存的实验包含 7,043 名客户，按流失标签分层划分为 5,634 条训练样本和 1,409 条测试样本，随机种子为 42。模型由训练集五折交叉验证的平均 AP 选定。

| 模型 | 五折 AP 均值 ± 标准差 | 测试集 AP | 测试集 ROC-AUC | 测试集 F1 |
| --- | --- | --- | --- | --- |
| 逻辑回归 | 0.6614 ± 0.0218 | 0.6334 | 0.8419 | 0.6040 |
| 随机森林 | 0.6504 ± 0.0230 | 0.6399 | 0.8374 | 0.5714 |

按交叉验证结果选择逻辑回归。随机森林的测试集 AP 略高，但不据此更换模型。F1 使用固定分类阈值 0.5；AP 为平均精确率，表中标准差反映折间波动，不是置信区间。

测试集有 374 名历史流失客户。固定选择排名靠前的 140 人，即测试集人数的 10% 向下取整：

| 排序方式 | 命中流失人数 | Precision@140 | Recall@140 | Lift@140 |
| --- | --- | --- | --- | --- |
| 逻辑回归 | 104 | 74.29% | 27.81% | 2.80 |
| 随机森林 | 108 | 77.14% | 28.88% | 2.91 |
| 短在网时长规则 | 87 | 62.14% | 23.26% | 2.34 |
| 随机选择的期望 | 37.16 | 26.54% | 9.94% | 1.00 |

Precision@K 表示入选客户中的历史流失比例，Recall@K 表示覆盖了多少历史流失客户，Lift@K 是入选流失比例与测试集整体流失比例之比。随机基线计算数学期望，因此命中人数可以为小数。

上述数值来自已保存运行 `outputs/project_v1/` 的 `metrics.json` 和 `policy_metrics.csv`。运行产物默认不纳入版本控制；下方命令会生成一份新的报告，依赖版本变化可能带来数值差异。

## 快速开始

使用 Python 3.10 或更新版本，以下命令均在项目根目录执行。

### 1. 安装依赖

```bash
python -m pip install -r requirements.txt
```

### 2. 准备数据

从 [Kaggle Telco Customer Churn](https://www.kaggle.com/datasets/blastchar/telco-customer-churn) 下载 `WA_Fn-UseC_-Telco-Customer-Churn.csv`，放入 `data/`。程序使用原始字段，其中 `customerID` 必须非空且唯一，`Churn` 为 `Yes` 或 `No`。原始 CSV 不纳入版本控制。

### 3. 训练并生成报告

```bash
python run_project.py --data data/WA_Fn-UseC_-Telco-Customer-Churn.csv --output outputs/project_v1 --test-size 0.2 --random-state 42
```

运行完成后，`outputs/project_v1/` 中会生成指标报告、分群统计、排序结果和评估图表，文件说明见[文件与输出](#文件与输出)。

`--output` 必须位于本项目内，且目录不存在或为空。重复运行时改用 `outputs/project_v2` 等新目录。缺少 CSV 时需先下载数据。核心实现位于 `churn_pipeline.py`，`run_project.py` 是推荐入口。

### 4. 查看结果

```bash
python -m streamlit run dashboard.py
```

看板自动列出 `outputs/` 中的完整报告，默认打开最近生成的一份，可以在页面“分析报告”中切换，不会重新训练。相对报告路径均以本项目目录为基准。

需要固定某次运行时：

```bash
python -m streamlit run dashboard.py -- --output outputs/project_v1
```

已有的完整报告也可直接查看，无需重训。旧版输出可能只有模型指标和图片，缺少分群和策略表；看板会明确提示并打开可用的完整报告，不会将旧模型指标与新分群表拼接。没有完整报告时，页面会给出生成命令。

## 分析与评估方法

1. 检查客户编号、标签和数值字段，将空白数值转为缺失值，再分层划分训练集与测试集。
2. 仅用训练集运行 [分群 SQL](sql/segment_analysis.sql)，统计合同类型、在网时长、月费分组的客户数、流失人数和比例，对少于 30 人的组做小样本标记。
3. 用 `ColumnTransformer` 和 `Pipeline` 组织缺失填补、数值标准化、类别独热编码和模型。预处理在每折训练数据上拟合，避免交叉验证时混入验证折信息。
4. 比较逻辑回归与随机森林，以训练集五折 AP 均值选模型，再报告两个模型的固定测试集指标。
5. 在同一测试集、同一 10% 名额下比较模型、短在网规则和随机期望。同分时按客户编号排序，分类阈值 0.5 不参与名额选择。

看板分为“客户差异”“模型验证”“触达排序”三页。特征重要性来自随机森林，用于描述该模型，不能当作逻辑回归的解释。

## 使用限制

数据是客户快照，缺少事件日期、预测时点、后续观察窗口和干预记录。分群差异只能说明关联，不能据此推断流失原因、未来某个时间窗口的流失，或挽留措施的收益。

该公开数据已参与项目开发分析，固定测试集结果属于可复现的公开数据基准，不是独立盲测。排序分数未经概率校准；带有历史标签的入选名单只用于离线方法比较。
